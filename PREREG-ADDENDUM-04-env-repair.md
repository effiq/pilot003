# PREREG-ADDENDUM-04 — Engineering Disclosure: builder-environment alignment + stage-07 output-capture patch

**Date:** 2026-10-09 (UTC)
**Status:** Engineering disclosure after execution start. No design, threshold, seed, arm, or recipe content changed. ADDENDUM-02 remains the governing protocol; this addendum supersedes the stage-07 hash listed in ADDENDUM-03 §5.

## 1. Environment alignment (builder side only)

The a2-smooth build — the first real `llmcompressor` invocation of this pilot — exposed a dependency-envelope mismatch that pure import checks cannot detect:

- `llmcompressor 0.12.0` fails at recipe-application time under `transformers 5.17.0`: its MoE registry eagerly imports `GraniteMoeParallelExperts`, a class removed from transformers between 5.10.x and 5.17.0. (The measured model, Qwen2.5-14B-Instruct, is dense; the failing import is registry boilerplate, not a code path the arm uses.)
- `llmcompressor 0.14.0` (which lazy-loads that registry) was trialed and rolled back the same hour: it imports `compressed_tensors.entrypoints.convert.exec_jobs_dynamic`, an API added after `compressed-tensors 0.17.0`, which is pinned exactly by the measurement engine (`vllm 0.31.0` → `compressed-tensors==0.17.0`). The measurement engine's dependency set is treated as untouchable.

**Resolution:** `transformers 5.17.0 → 5.10.4` — the exact floor of vLLM 0.31.0's own declared range (`transformers>=5.10.4,<5.18.0`) — keeping `llmcompressor==0.12.0`. Verified before touching the measured model: `GraniteMoeParallelExperts` confirmed present in the 5.10.4 wheel, and a full-chain smoke test (Qwen2.5-0.5B-Instruct → SmoothQuant + FP8_DYNAMIC one-shot via `Dataset.from_list` → checkpoint → vLLM `compressed-tensors` serve → generation) passed end-to-end on the pod.

- Serving-side impact: none material. transformers is used by the serving stack for config/tokenizer loading only; vLLM's engine and kernels are unchanged; the tokenizer library files on disk are unchanged; both completed arms (R, a1) were generated by vLLM under an unchanged vLLM version. The transformers downgrade is recorded here and in the run environment anchors.
- Builder version remains `llmcompressor 0.12.0` and continues to be recorded as provenance per ADDENDUM-02 §2; the measured artifact is the checkpoint hash.

## 2. Stage-07 script patch #2 (output capture)

After the first successful checkpoint build (a2-smooth, 16 GB, `config.json` present, custody logs written), the stage died at server start with a malformed model path. Root cause: `build_checkpoint` is invoked via command substitution (`cdir="$(build_checkpoint …)"`), and two stdout writes inside the function were captured into the returned path: the `note()` progress banner and the builder's success `print()`. Both are now redirected to stderr. This defect was invisible in the sandbox because the mock-build path writes its diagnostics to stderr only, and it was invisible pre-patch because the builder had never before exited successfully. Stages 08/09 do not capture builder stdout into variables and are unaffected (their hashes from ADDENDUM-03 §5 stand).

## 3. Impact statement

- The a2-smooth checkpoint produced by the failed run is **valid and retained**: it was built by the disclosed patched script under the aligned environment; its full-tree sha256 was recorded to the run custody logs at build time. On resume, stage 07 detects the existing checkpoint and reuses it (no rebuild) per the frozen resume design.
- Zero measured data existed for checkpoint arms before this patch; R/a1 artifacts stand. Arms, recipes, seeds, thresholds, gates, and judge-panel rules are untouched. `arms-manifest.json` (`5f1a1972…`) and all Pilot 002 anchors are unchanged.
- Root-cause lesson carried into engineering rules: mocks must replicate the real path's *output-channel behavior* (stdout vs stderr), not only its return values; and builder-facing call sites require a real-package smoke test before freeze. Both rules were stated in ADDENDUM-03 §3 and are reaffirmed here with a second instance.

## 4. Cost disclosure

The dependency-alignment trials and the four failed/aborted a2 attempts consumed GPU time without producing measured artifacts; the successful a2 build (~8 minutes) is retained. Figures go to the internal ledger; the public cost summary in the final verdict covers producing runs.
